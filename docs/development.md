# 开发约定

主要运行环境为 Windows x64，Python3.11与Node.js24。先读README安装依赖，FFmpeg与模型单独安装。

源码分为项目根目录的Python内核、`electron-ui/`界面与`desktop/`历史WinForms入口。界面构建不把Python环境打进ASAR。便携包使用官方Python3.11.9嵌入式x64环境；共享候选按完整目录内容哈希合并相同基础依赖，CPU/DirectML的ONNX Runtime与差异依赖继续隔离，保留许可。

## v1.0.1 界面与发布

窗口按钮由 DOM 绘制并进入同一个根视图快照；关闭 native titleBarOverlay 后，通过受限窗口 IPC 处理最小化、最大化/还原和 close。close 仍调用 win.close，沿用现有断点保存与设置写入保护；最大化状态由主进程事件同步。按钮位于独立 portal，设置面板打开时仍可操作。

surfaceGeometry.ts保留底边连接导航与凹角；surfaceMotion.ts从实际屏幕几何重定向，并处理可见性暂停。FluidLayout.tsx在DOM更新前采集真实位置：首次入场、视图切换或尺寸变化使用短淡入，尺寸不变的重排只过渡位置。动画期间保持最终布局宽高，不缩放卡片或文字，卡片边缘维持规整圆角；减少动效时直接到终态。常规与全屏视频均使用 contain，媒体容器跟随实际显示比例；只有列表封面使用 cover。常规与全屏控件以透明底覆盖在画面底部，不额外增加播放器高度；文字和图标添加阴影，本局战绩随控件隐藏。结果标记位置仍使用结果发生时间，回看位置通过已有开枪/正伤害时间线按连续过程计算；同目标延迟击杀关联此前击倒，缺失旧时间线时回退到结果前6秒，不额外做OCR。滚轮监听仅绑定展开的播放器：常规模式只拦截音量控件，视频画面保留页面滚动；全屏模式额外允许画面滚轮调音量，卸载时移除监听。VirtualClips只挂载视口附近的卡片，选中卡片保留DOM和唯一video。

tests/v5-ui-validation.cjs与tests/v5-theme-validation.cjs使用隔离目录中的合成媒体及元数据，验证自动历史库、真实比例/旋转、事件seek、统计展开、320ms双沿中断、四主题、减少动效和最小窗口。合成数据不进入生产库或发布包。真实性截图使用已导出录像，不以Figma图片替代。

在electron-ui设置APEX_PACKAGE_OUT=release-v5构建独立目录，避免覆盖正在运行的旧程序；回仓库运行scripts/build-portable.py。默认暂存目录是publish/v5-shared，目标存在时拒绝覆盖。CPU/DML输入必须都是Python3.11 x64。可通过--runtime-source指定既有双环境便携包，逐文件核对FILES.sha256.json后复用依赖，不需要重新下载。输入、产品模块和依赖采用白名单；相邻原生库组成完整共享组，任一成员不同就整组隔离。ZIP按固定时间戳和文件顺序生成，便于用相同输入重复构建。

`--shared-runtime-source`复用已有独立推理报告且逐文件内容不变的运行库，资源和加载器也必须一致。内核代码不变时复用对应检查；内核代码变化时补一个便携worker冒烟，不重复已通过的CPU/DirectML库推理测试。

EXE 安装包由 `scripts/build-installer.py --bundle publish/<构建目录>/Apex-Clipper-<版本>-Windows-x64 --iscc <ISCC.exe路径>` 生成，使用 Inno Setup 7。编译器采用可解压的工具包，使用前核对其 Authenticode 发布者为 Pyrsys B.V.。脚本校验便携包的既有报告和逐文件清单，只打包清单内文件，并加入固定 SHA256 的 FFmpeg 9.0.2 官方供应包及许可。FFmpeg ZIP 放在 `publish/downloads/ffmpeg-9.0.2-essentials_build.zip`。所有依赖、EXE、校验报告与临时文件均留在被 Git 忽略的 publish 内。

安装包默认安装到当前用户的 LocalAppData/Programs，不要求管理员权限；开始菜单入口直接运行应用，桌面快捷方式可选。`/PORTABLE=1 /DIR=<隔离目录> /VERYSILENT /NORESTART` 可用于一次最小解包与启动检查，不写卸载登记或快捷方式。安装包已附视频工具，可离线运行。只检查安装文件完整性及启动，复用内核已有验证；测试目录在检查后清除。

v1.0.1 保持安装器 AppId `{AF948615-855F-4699-8640-11A9E2F08854}` 与用户数据路径兼容。更新器仅接受本仓库同版本的 EXE、有效大小和 GitHub SHA256；流式校验后通过 Electron relaunch 交接到隐藏的 PowerShell helper，等待旧进程退出，再在当前目录安装并重新启动。便携版使用 /PORTABLE=1，安装版沿用卸载登记；不强杀窗口或后台任务。下载在用户数据 updates 目录，有跨进程锁与清理机制。旧版本（如 0.2.0，仓库中最早且唯一的旧 tag）不具备安装逻辑，第一次通过原更新入口打开 Release 下载 EXE，之后使用应用内“下载并安装”。

两个runtime/*/python.exe入口保留。python311._pth只包含当前模式、包内源码与runtime/shared/Lib/site-packages，不读取PYTHONPATH或系统Python包。sitecustomize检查必需资源、保留AddDllDirectory句柄，并处理共享pywin32.pth；不会将另一模式的ONNX Runtime加入DLL搜索目录。Windows对多个新增DLL目录不保证顺序，因此构建时拒绝当前模式内不同内容的同名DLL。依据：[Python嵌入式路径](https://docs.python.org/3.11/using/windows.html#finding-modules)、[add_dll_directory](https://docs.python.org/3.11/library/os.html#os.add_dll_directory)、[Windows DLL搜索规则](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-search-order)。

发布ZIP最外层仅有 Apex Highlight Clipper.exe 和 resources/。Electron 放在 resources/desktop，内核、runtime、模型、配置、文档与文件清单集中在 resources。启动器首次通过 resources/scripts/setup-ffmpeg.ps1 准备共用 FFmpeg，升级后继续复用；默认输出在系统视频目录，设置、历史与缓存仍使用既有用户数据目录。启动器由 Windows .NET Framework 自带的 C# 编译器生成，无控制台窗口。

安装器兼容旧的平铺目录：仅清理由旧文件清单列出且哈希仍匹配的程序文件，保留自选输出、断点和用户改动。旧更新脚本固定重启 app/Apex Highlight Clipper.exe，升级期间临时提供兼容启动入口，桌面进程确认内容与根启动器相同后清理。文件清单移至 resources/FILES.sha256.json，清单路径仍相对整个便携目录。

只运行本次改动直接影响的最小检查，复用同一代码状态下已通过的结果；不因发布重复运行全部界面组合。共享运行库改动需要验证包移出项目后两种provider的OCR、模式切换、重启、缺资源错误，以及一个媒体seek场景。发布与push需要当前任务明确授权，确认目标commit、CI和包清单后再操作。

## 测试

可选 HUD 信息使用 optional-hud-v11。玩家名保留二值、彩色和灰度视图；仅当多语言读数均为 ASCII 时，才使用已随包提供的英文模型 numeric_rec_en_v4.onnx 复核。队友名称左侧留四像素边距，避免相邻图案被读成首字母；本人账号仍使用原边距。两个清晰视图一致的拼写不会被批量多数票改成另一个拼写；同一画面的不同视图不增加跨帧票数。游戏实际绘制的空心方框须经两种视图和图像轮廓共同确认，不能把 OCR 产生的占位符当成姓名。技能识别补充去除场景及人物信息的游戏内图形模板，先排除仅匹配充能条的候选，再比较候选间差距。首轮补读在各个未确认字段之间分配，优先靠近实际露出的画面，最多六帧。段位徽章沿用缩小匹配，分级文字回到原生像素读取，分级自身也须双帧一致。

真实回归仅复用已有问题片段，检查单段/批量重读和最终界面名称；不能用隐藏名称或全部变成未知来替代修正。固定输入的重复性检查与识别准确性检查分开记录，记录保存在忽略的输出目录。


Python单元测试使用临时目录和模拟调用，公开仓库不依赖开发者的私有录像路径。GUI纯逻辑测试在 `npm run build` 后执行 `npm test`。需要真实录像的性能、OCR与界面联调另行准备本机素材；这些运行记录不提交。

调整识别规则时检查伤害/击杀、切枪、零击杀助攻、本人倒地后队友续战、字幕被击倒负例和模糊提示。调整时间网格时核对绝对PTS，不能通过改文件编号伪装成更密集采样。

## 数据与发布

新任务使用任务格式 v2。`export_layout=task`（默认）在所选输出位置创建本次整理文件夹，`flat` 直接混放在输出位置；两者均只输出 MP4，短任务与源文件标识防止同名覆盖。JSON / CSV、分析、导出清单与断点统一保存于 `<dataRoot>/tasks/<taskId>/`。桌面端的 dataRoot 默认使用 Electron `app.getPath('userData')`，检测到旧版 `%APPDATA%/Apex交战剪辑/preferences.json` 时沿用旧目录；可用 `APEX_DATA_ROOT` 指定隔离目录。直接运行 Python 的 Windows 默认值为 `%LOCALAPPDATA%/Apex Highlight Clipper`。旧版 v1 任务继续按原目录读取及续接，不静默搬动已有成片。

自动布局由 `hud_layout.py` 按左/右/中心、顶部/底部锚点生成，最多四次直接 seek 比较 HUD 标记，不按文件名或编码宽高猜拉伸。每个任务项冻结实际布局，缓存摘要和未完成任务保护使用该布局。无可靠标记时保留未确认状态；非标准 HUD 缩放仍可能需要后续校准。

交战阶段仅保留定位和战果需要的画面信号，不执行枪械名称、账号、队友、英雄或段位识别。`hud_enrichment.py` 是整理后和片段库补充共用的入口，每个片段先取三张不同画面，未确认时先补三帧，至少两帧一致才确认名称/武器/英雄/段位；只原子追加 export.json 的 recognition.hud_info。武器、英雄或段位仍未确认时，再检查六个未覆盖时刻；只有实际读到候选才补其前后各40毫秒的原生帧，不降低识别门槛。这个阶段只读取仍待确认的所选字段，已确认及未选择的字段不参与补读；相同 PTS 不增加票数。名称行按多个尺寸匹配语音图标，裁掉图标再识别，并过滤战队标签。本人按原录像、队友按同局槽位汇集实际多帧姓名，只用重复且占优势的拼写校正相近误读；不跨局合并不同中文姓名。手动重新识别只使用本次所选片段的证据。IPC 只接受当前片段库注册的导出路径，并与识别和维护互斥。历史战績、视频文件与交战边界不因补充而改变。

旧清单缺少对局标识时，仅从来源身份和片段边界均匹配的 `analysis.json` 恢复对局结束事件分组；分析不匹配时不跨片段套用队友姓名。固定昵称区域允许较长的纯数字 ID，昵称边缘的占位方框可移除，内部 OCR 缺字仍视为未知。只有图像中确实绘有较小的空心方框，且两种视图及两帧确认时才保留游戏可见的方框昵称，同时标记 rendered_placeholder 并保存原读数；不能猜补方框背后的字符，也不能丢掉整个玩家。英雄技能模板只在按钮中央搜索，避免把梯形边框识别成技能。

结果提示的动作、姓名与积分分别处理：根据 CTC 字符位置裁出姓名，同时用动作图形和积分边界保留首尾字符；拉丁姓名复用包内英文模型，彩色和灰度视图一致且至少两帧确认后展示。每条结果先读三帧，清晰读数存在缺少首尾一至两字的冲突时，才围绕完整读数补最多五帧；不能追随另一条无关战果。完整拼写票数相同时保留未确认，不能选择一个猜测。战队标签兼容明确的中英文方括号，保留 raw_name；没有实际括号证据时不凭字母串猜标签。段位图形还核对饱和颜色，避免黄金和白金的相近轮廓互相干扰。游戏内技能符号与官网技能插画分别存放；未充能的条纹背景采用行背景对比处理，不能通过降低阈值填入英雄。

片段库可另外选择“战绩数字”“敌人姓名”复核，支持未确认项与重新识别、所选文件、工作信息和停止；这些字段不混入新建任务的五项 HUD 选项。校正文件位于软件数据目录 recognition-corrections，用原统计内容和任务目录共同生成键，并按记录加跨进程写锁。只有与当前导出视频身份匹配、起止各有两张不同 PTS 的原生证据才能替换已有数字；原生复核仍待确认的字段在界面显示未知，原数保留在记录中。已证明的下限单独标记，不能把无法确认的旧数当成下限。原始 statistics.json、录像和交战边界不改写。停止后刷新片段库，保留已经完成的校正。

原生本人视角证据使用 self-hud-view-v3：绿条队友观战及同时出现红色或蓝色顶部导航和底部红条的敌人观战均排除，不改变历史对局结束规则。成片末端全部为观战时，有限回看更早的成对原生帧；由此前本人画面读到的增量只作为下限。旧视角版本的证据不能覆盖已有数值或填入缺失值，校正签名还包含视角规则以避免复用旧结果。

战绩数字使用包内中文 v4、中文 v5、英文 v4 三套模型，同一裁片至少两套一致，再要求两个不同 PTS 的画面确认。完整击杀、助攻、参与图标用于确定各自数字边界，四位伤害扩大裁框并避开段位。native_numeric_method 标识为 numeric-three-model-v3，模型权重和模板内容都进入校正签名。相邻图标不能切入数字，同一画面的不同预处理不能算多帧。原生复核未确认的首尾保留未知，不能填入旧截图或观战值；本局 HUD 总数也须有当前方法的两帧末值证据。

桌面启动 Python 使用 -B、显式 UTF-8 和隔离的 pycache_prefix；隔离目录不写入缓存，避免 ZIP 的固定时间戳与同大小源码导致升级后继续读取旧字节码。HUD 子进程沿用同一个前缀，CPU 回退也不加载相邻旧缓存。

常玩信息按 match_key 去重；旧记录回退到源录像。英雄来自本人技能 HUD，使用 assets/legends 中官方 EA 图标与来源清单，遮挡或冷却数字可能导致无法确认。英文中心结果提示需高置信语法及相邻两帧相同目标；语法版本独立于原 OCR 日志，解析修复复用原始文字记录，统计检查同时包含解析版本，避免复用旧计数。

`validation`闲时维护：最多保留最近3次测试目录和3次识别缓存，旧测试目录超过7天也会回收；保留最近3份摘要、用户标注及最后任务入口。清理器读取已登记输出根和任务记录，保护未完成任务、缓存代次和近期缓存引用的采样目录；仅处理选定 dataRoot 下的 validation（未指定时使用开发目录），核对全部子项后回收目录，不跟随目录链接。启动后每日维护一次，批次结束后补充维护，开始识别时停止维护。手动预览：`powershell -File scripts/cleanup-validation.ps1 -DataRoot <软件数据目录>`，加`-Apply`才实际删除。统计保存在任务数据目录，成片保存在用户选定的视频输出目录。

封面缓存限制256MB，60天未使用则回收；Chromium磁盘缓存限制64MB。临时请求随进程结束清除，异常残留超过7天回收。打包器标记自身产物并调用`cleanup-generated.ps1`：便携包保留最新2个成功版本，Electron中间包只保留1个，失败包自动回收，运行目录与本次运行库输入跳过。未标记的目录不会自动按名字删除。

录像、分析缓存、模型、虚拟环境、构建包、本机配置和内部交接记录均在 `.gitignore` 中排除。不要提交鉴权信息或个人路径。小型HUD字形模板用于当前校准配置。

保留原任务版本与断点，升级不能静默改写历史成片。改名时保持旧的本机用户数据路径兼容。测试回收逻辑只使用专门生成的副本，不回收用户原始录像。

主题固定使用官方MCU0.4.0的SchemeVibrant、contrast0、spec2021、platformphone。任意seed经HCT/调色板生成语义色，同帧合并、缓存64种组合。库索引保存在用户数据目录library.json，发现已登记输出根与软件 tasks 目录，不遍历用户磁盘；读取历史库不改写任务与成片。

首页 HUD 与过滤开关紧挨导入按钮，开关启用后仅显示三角按钮，由用户手动展开；关闭时收起，再开启仍保持收起。展开只改变布局高度，不缩放内部文字。新任务默认 gap=10、pre=6、post=6；旧任务仍沿用冻结值，历史偏好中的旧默认组合仅迁移一次。无损校验开关与自动校验阶段已移除；原始流复制导出及独立回收站开关保留。

FFmpeg 启动引导固定使用 `%LOCALAPPDATA%/Apex Highlight Clipper/dependencies/ffmpeg/9.0.2`，以文件哈希验证共享副本。当前包、相邻旧包与已安装版可离线迁移；只有缺少已验证工具和 ZIP 时才下载。Python 工具查找与 Electron 缩略图查找保持相同优先级：显式环境路径、共享目录、包内工具、原有后备路径。安装器用 `-NoDownload` 播种共享副本；卸载单个应用版本不删除共享目录。

姓名中的字母与数字歧义由实际裁字复核：两种保留笔画的视图须得到至少两个模型一致结果。裁框用背景色补边，不能复制边缘笔画；低分单字猜测不能令已有队友消失。只有可信的冲突才增加有限补读，优先靠近字形已确认的画面。同一人的跨帧证据中，至少两帧清晰完整拼写可排除缺尾字的短读数；不同人的名称池不采用这条规则。

难读战果在原有三帧及前缀复核仍未确认时，才有限补读提示末端并使用 PP-OCRv5 server。原模型实际字符与独立模型正反灰度视图须一致；前导方块必须另有图像形状证据，最终仍须两个不同 PTS 确认。模型固定 SHA256 位于 target_name_reader.py，构建时准备并随包分发，运行时不下载。用户提供的正确写法只作为离线核对答案，不进入运行时配置、姓名映射或识别器参数。

战果姓名解析使用 target-name-v13。末尾点号和词间空格属于昵称，不再清除或用字母数字键合并拼写。难读英文在事件前 0.6 秒和提示稳定区最多补读 12 帧；仍冲突时，仅在最多两个实际清晰读数附近补八帧，不跨越相邻同类事件。根据原模型实际发出的括号位置排除战队标签；词间空格须由两个实际视图在对应位置读到，在附近字间谷底裁词，避免切掉宽字母。只有分词位置检查可接受接近的原始字母读数，输出字母数字仍须与原模型完全一致。以英文 v4、v5 独立读数复核，基线小点另用亮度形状的数量与等间距验证，不固定为三个点。每个词必须两模型同意且至少一方达到高置信度，最终仍要求不同 PTS 的完整拼写一致。保存逐词模型与点号图形证据，不能套用验收答案。

DirectML 模型会话在识别工作进程的整个生命期保留，包括两个片段之间；仍串行执行设备调用。缓存最多八个不同的模型身份，达到上限时报错而不在工作中逐出设备图。进程退出后由系统释放；避免 ORT 1.24.4 在上一片段的独立模型销毁后，下一个片段首次 Run 触发本机访问冲突。

姓名字段算法独立标记为 player-names-v12；容器格式仍是 optional-hud-v11，武器、英雄、段位字段继续使用原版本标记，姓名升级不令其他已确认字段失效。实际读到假名的姓名才加载固定日文模型；按 CTC 位置去掉战队标签，再让两种视图核对字符族。只有模型实际提出了大小假名变体，才根据同一行的字高、顶部和基线选择实际字形；不能把天然较矮的普通假名统一缩小，也不使用词义或昵称表。尺寸有争议的字不充当字号标尺；未确认尺寸不进入最终投票。原始读数、两模型字词读数与尺寸证据保留在元数据。字形已确认的拼写不被跨片段多数票改回，清晰字形证据也用于选择有限补读位置。

账号仍未确认时，最多检查八个时刻的名称行形状，排除贴图遮挡和截断读数，再选最多三张清晰画面读取；遇到可信读数只比较相邻原生帧的独立实际输出，不把该读数当解码提示。较低分的英文词必须与另一套模型两视图逐字符一致；英文模型候选可由多语言模型裁去实际战队标签后的正文读数验证，验证器不提出或替换昵称。至少两个不同 PTS 的完整清晰读数才能排除遮挡画面里的相近误读；原始候选和图像证据保留，清晰已证实的拼写不被批量多数票覆盖。

现有成片计分基线逐项检查最早有效原生读数，仍限定在视频起点后80毫秒内，并保留双帧一致要求。第一张损坏或未读出该字段的帧不挡住随后有效读数；最早有效读数与后续多数值不同，或第一次有效读取已超时，仍不能认证为片头基线。

片尾最后一张画面有字段未读到时，该字段较早已确认的数值只能表示下限；完整读取的其他字段不受影响。Python 核对和界面适配均从原始 end_frames 推导，旧记录没有新标记也会检查。播放器不把被遮挡前的数值当作当前本局精确总数。末值低于基线时，即使首尾各有双帧，也不能认证为可靠增量。

数字 OCR 额外检查高亮前景的字符分离，排除右侧界面斜线及不在同一文字行的碎片。只有图像中出现比原读数更多的独立字形，才复核漏字；另一阈值下仍粘连的文字可提供模型读数，但须有同帧独立字形数量支持。新拼写必须保留原有数字顺序，并由两模型高置信一致或三模型一致且至少一方高置信支持；不同候选冲突则保留未确认，不选择较大的数。多种图像阈值不增加画面票数，最终仍需不同原生 PTS 确认。

## 从 README 下沉的实现规格

以下原写在一份面向用户的说明里，随该文档改为用户视角而移到这里；都是设计与实现口径，不面向用户。

**界面与主题。** 标题栏 36px，底边连接导航与凹角由 surfaceGeometry.ts 保留，慢速斜向手柄图案周期 32s、尺寸 160×160（v3.css:6,19-20）。视图切换通过浏览器卡片快照过渡位置与外框，实际列表布局保持稳定；尺寸不变的纯重排只过渡位置，快速反向切换取消上一轮（libraryViewReveal.ts:13-35）。明暗主题固定使用官方 MCU 0.4.0 的 SchemeVibrant、contrast0、spec2021、platformphone（theme.ts:1,11）；任意 seed 经 HCT 与调色板生成语义色，同帧合并、缓存 64 种组合。标题换肤用圆形遮罩从按钮实际点击位置扩散（themeReveal.ts:18-41），开启减少动效时直接到终态。角色形象默认关闭，当前统一使用 Blanca 俏皮工作动作第三版；旧 flat / sketch 偏好保留兼容读取，界面不再提供旧样式选择；开关沿人物 → 虚线轮廓 → 消失往返，并播放消失 / 复原音效（blancaState.ts:5,28-29、mascotAudio.ts:6、Mascot.tsx:34,67）。

**识别内部机制。** 索引加速为唯一扫描方式，新任务的 scan_mode 在 electron-ui/electron/protocol.ts:35 被强制写为 indexed，仅旧任务保留冻结值；索引粗查要求起始 PTS 为零的 H.264 MP4/MOV（indexed_coarse.py:37-42）。可选信息首轮取三帧，未确认时首轮补读最多三帧（hud_enrichment.py:92,186-191），之后仍会在清晰 HUD 附近继续补读最多六个时刻及相邻原生帧（:328-346）；账号搜索另有最多八个时刻（:347-357）。枪名走独立窄行批次并比对已知武器词表，导出前补回枪名识别（weapon_reader.py:165,273、app_worker.py:265）。HUD 布局适配最多直接检查 8 个分散时间点（4 个，时长 ≥600 秒再加 4 个），确认即停（hud_layout.py:94-112）；布局未确认且有活动时报识别失败（:115-118）。

**日志、更新与计时。** 诊断日志单文件上限 1 MB、总量约 20 MB、保留 7 天（electron/diagnostics.ts:8,51）；诊断包含最近日志、运行环境、剪辑参数、任务状态、近期错误摘要与 GPU 基本信息，隐去本机路径，不含录像、封面、完整任务文件或 HUD 账号识别结果（main.ts:215,245）。自动更新检查间隔 24 小时（updates.ts:6），安装包只接受同仓库、版本号三段式、大小 ≤1 GiB 且 sha256 为 64 位十六进制的资产（updateInstaller.ts:30）；更新下载缓存的清理规则见 updateInstaller.ts:27。队列计时每录像每秒刷新，完成或停止后冻结，等待与暂停不计时，续接累计（electron/processingTimes.ts:14-36），历史已完成录像用阶段统计补显示（:5-12）。

**数据与发布。** 输出目录只放成片；任务记录、JSON/CSV 分析、导出清单与断点统一在 `<dataRoot>/tasks/<taskId>/`（app_task.py:117-135）。桌面端 dataRoot 默认取 Electron userData，检测到旧版 `%APPDATA%/Apex交战剪辑/preferences.json` 时沿用旧目录（main.ts:26,33）；直接跑 Python 时默认 `%LOCALAPPDATA%/Apex Highlight Clipper`。旧任务按原目录读取与续接，不静默搬动已有成片。FILES.sha256.json 位于 resources/，清单路径仍相对整个便携目录；SHA256SUMS.txt 由 build-portable.py 在打包时生成（:241），不在源码树中。


Blanca 第三版原 PNG 保持原字节，运行时按 `playful/sprites.json` 的主体/道具裁切路径与脚底锚点绘制；只缓存 35 个成帧结果和至多两张已解码原图。四姿态停留分别为 4、4、4、6 秒，每轮 18 秒；相邻姿态与进入行走使用 180ms 平滑混合，混合完成后继续休眠，不改变动作时长；换工序前先用单张方向图移动四跳（约 2.2 秒），到点停稳后以 240ms 缓动侧翻，在最薄一帧切图。工序在移动期间快速变化时合并到最新目标，不重启整段步行动画；减少动效时直接切到稳定姿态。导入脚本只复制原 PNG 并派生矢量裁切元数据，不生成行走逐帧图。

个性化设置分别保存人物与背景帧率（1–240 FPS，旧偏好默认人物 30、背景 60）。人物只在移动、侧翻、淡入淡出等动态期间按帧率上限更新，稳定姿态仍休眠；保留刷新间隔余数以免累积降帧。背景在原 32 秒循环上按帧率离散取样，降低帧率不会改变移动速度。减少动效和窗口隐藏时的暂停规则继续优先。

本地界面预览使用根目录 `预览Electron界面.cmd`，始终启动当前源码，不选择旧的 release 目录。启动器仅在源文件或资源比现有构建更新时执行构建，复用未变化的构建；单次启动日志覆盖写入 `electron-ui/output/preview/launcher/launch.log`。

预览入口只隐藏 PowerShell 辅助进程，Electron 主进程必须使用正常显示方式启动；Windows 的 SW_HIDE 会抑制第一次原生窗口显示，造成后台运行却没有窗口。`--preview` 使用单实例锁，重复点击恢复并聚焦现有窗口。

主页 idle / importing 使用用户单独提供的 `playful/idle.png` 静态待机原图，沿用脚底锚点与杂点遮罩。应用 SVG 图标由用户提供的场记板人物图做彩色曲线描摹，含真实路径、不嵌入 PNG；窗口 PNG、安装器与 EXE 的多尺寸 ICO 均从 SVG 派生。重新导入使用 `scripts/import-blanca-icon.py --source <PNG>`，仅素材制作时需要 vtracer / resvg-py，不加入产品运行依赖。

播放留在同一个片段库，由同一张片段卡片连续形变切换布局。常规模式为左视频、右侧可扩展多列的片段列表，详情在播放器下方展开；宽屏模式为上视频、下横向列表，详情默认收起，以卡片从画面右侧向左滑入。宽屏卡片按画面与工具栏内容定高，与横向列表整体居中；高度预算从工作区扣除列表、间距和内边距计算，避免用自身内容高度循环测量。宽屏详情按钮使用右侧栏开关图标，常规下方详情才使用上下箭头。两种模式共享同一视频元素，保留播放时间、筛选、原视图与各列表浏览位置；横向轨道按可见范围虚拟化，支持滚轮、箭头和定位当前片段。只在用户点击全屏时进入原生全屏。

常规模式沿用原播放器与右侧列表的宽度分配，列表在自身容器宽度达到 356px 时改为双列紧凑卡片，保留日期、英雄武器、击杀、助攻、击倒、伤害。增加可见片段通过列表内部排布实现。宽屏模式优先观看：底部单行轨道保留片段文件名、原录像名、时间、英雄武器与四项战绩，以紧凑排布展示；轨道高 160px，有筛选标签或识别进度时增至 188px，不改变筛选与排序偏好。分组标签显示在对应横向分组的首项上方。

ClipCard 在库视图与播放状态共用同一 article 和封面节点；播放行为通过 useWatchPlayer 组合到卡片内。稳定的 portal host 在原网格槽位与观看区域间移动，展开、收起及切换宽屏使用 460ms 的实际外框位移与尺寸过渡，封面等比缩放。动画层通过原子 DOM 移动保留正在播放的视频，按工作区裁切，并在完成后回到正式布局。详情初始高度在整卡形变前确定，交互展开时仍保留自身动效。筛选排除当前片段时仍保留其卡片实例，源槽位隐藏，播放不中断；虚拟列表只测量槽位及导航条目。

详细、网格、列表三种视图的卡片操作均向右收拢。播放详情开关与查看文件、重新识别、分享、删除放在同一操作组，战绩摘要放在组外。常规播放器下方详情按容器宽度横向分组，标签在值上方；宽屏片段轨道与播放器外框等宽，不铺满两侧留出的背景区域。

浏览筛选面板按自身容器宽度布局：基础条件默认双列，500px 起三列、840px 起四列；搜索在三列布局中跨两列。击杀、助攻、伤害和时长单独成组，窄面板两列、500px 起四列；控件统一 32px，保留选中后清除按钮的伸缩动画。播放布局只控制面板位置，不覆盖其字段列数，播放器和列表的宽度分配不变。

排序分片段伤害、击杀、助攻、击倒与全局伤害、击杀；全局值仅取已有 roundTotals 的本人 HUD 累计值，不用片段值或跨片段相加补造。未知值在升降序中始终置后。最近整理和录像时间按日期分组；战绩排序按观察值分组，片段伤害每 100、全局伤害每 500 一组，其余计数按各值分组，保留当前排序方向。没有启用任何筛选时隐藏当前筛选栏。

库列表改为最小高 96px 的紧凑横向卡片，1920px 起三列，较窄窗口沿用一或两列；展开详情仍按内容增高。网格和详情卡片的武器标签与操作区同样右对齐。常用控件、信息栏与弹出菜单统一使用 14px 圆角，外层卡片使用 24px；标题栏连接曲线和圆形控件沿用各自几何规则。首页继续按钮跟随进度文字，更改按钮跟随输出位置，开始按钮仍位于操作栏末端。

HTML 全屏显式以视口宽高布置播放容器、媒体帧与底部控件，独立于内嵌画面尺寸；21:9 在 16:9 视口中保留黑边。全屏移动事件在文档层同步唤出控件，静止时继续自动隐藏。
