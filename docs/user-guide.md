# 使用补充说明

README 讲的是怎么上手和有哪些功能，一份文档装不下所有细节。这里补的是几个用户常问、但 README 放不下的地方：片段库里的补充识别怎么选，删掉的片段去哪找，更新失败该看什么，HUD 认不出来能做什么。

写法说明：每条关键行为后面都跟了源码位置，路径从仓库根算起，可以自己打开核对。这里只写能在源码里核对到的行为；核对不了的地方，本文不替它编一个说法。

## 片段库里的「补充 HUD」

入口在片段库工具栏，按钮写着「补充 HUD」，点开后面板标题是「补充已导出片段的信息」（electron-ui/src/ClipLibrary.tsx:71,87）。剪辑时没开「整理时补充 HUD 信息」，或者想给以前的片段补账号、武器、段位，都从这里补。

面板上要选两组东西。**识别模式**：

- 「未识别片段」是默认值，只补你勾选字段里缺失或还没确认的部分，已经确认的结果原样保留（ClipLibrary.tsx:87）。
- 「重新识别」会把勾选的字段整个重读一遍，读到没确认的会提示你复核，原始战绩记录不动（ClipLibrary.tsx:87）。

**范围**决定动多少段：

- 「当前筛选的 N 个片段」跟着片段库眼下的筛选结果走，N 就是面板上实时显示的那个数。注意它认的是当前筛选后的片段，不是你的全部历史（ClipLibrary.tsx:22,32-42,87）。
- 「当前播放片段」只处理选中的那一段，没有选中时这个选项是灰的（ClipLibrary.tsx:87）。

字段清单：本人账号、武器、队友、英雄、模式/段位，另外还有三个更重的 —— 战绩数字、敌人姓名、战果相关武器（electron-ui/src/HudSettings.tsx:5-6）。

跑起来后面板里会出现进度条、「当前片段」的文件名、这次走 GPU 还是 CPU，还有一个「停止」按钮，那个按钮调的就是主界面同一个停止（ClipLibrary.tsx:87）。识别期间面板里的控件都锁住，工具栏按钮显示「正在识别…」（ClipLibrary.tsx:71,87）。

结束或停止后仍保留本次进度和状态，切换页面再回来也能查看。还有未确认信息时提示核验，整组没跑成时提示重试；单段的「重新识别」按钮也能选择本次需要重读的字段（electron-ui/src/useHudEnrichment.ts、ClipActions.tsx、ClipLibrary.tsx）。

补充识别不能和别的活儿同时跑：剪辑、补充识别、片段回收、更新任何一项在进行，都会拒绝启动（electron-ui/electron/main.ts:187-188）。

## 删片段为什么要连点两次

第一次点删除按钮只是进入确认态（图标变对勾、旁边出现「确认删除」），第二次点才真的移走。悬停提示是「点击后需再次确认，才移至回收站」，确认态下变成「再点一次移至回收站；5秒后取消」（electron-ui/src/ClipDeleteButton.tsx:17-23）。

确认态有好几种撤销方式：5 秒没动作自动取消（ClipDeleteButton.tsx:10）；点到按钮以外的地方（:11）、按 Esc（:12）、窗口失去焦点（:13）都会取消。

删除走的是系统回收站，程序不直接删文件（electron-ui/electron/main.ts:74）。所以想找回来得去 Windows 回收站还原，程序里没有「撤销删除」这个界面。还原之后回到片段库点一下刷新按钮，让库重新读取（ClipLibrary.tsx:68）。

程序会把「这段是用户主动删的」记在用户数据目录的 clip-deletions.json 里（main.ts:37；clip_deletions.py:9-15），下次启动不会再把它当成文件丢失来报错。

原录像删不掉是故意的。删除按钮只出现在片段卡片上（electron-ui/src/ClipCard.tsx:60），主进程还会逐项核对：这个文件得是片段库登记过的成片、任务记录里要能找到对应的导出条目、真实路径必须落在成片目录内、而且不能等于该任务里任何一个原录像，任何一条不成立就直接拒绝（main.ts:67-72）。原录像要不要回收是首页「导出后移至回收站」开关管的事，和这里不是一个入口（App.tsx:122）。

任务跑着的时候删除按钮是灰的（App.tsx:93；ClipLibrary.tsx:89）；就算绕过界面，主进程在有剪辑、补充识别或更新进行中时也会拒绝回收（main.ts:66）。反过来也一样，正在回收片段时不让开新任务（main.ts:161）。

## 更新失败的时候看哪里

「启动时检查更新」默认开着，程序启动 3 秒后查一次，之后每 24 小时最多自动查一次（main.ts:61；electron-ui/electron/updates.ts:6,33-35）。想立刻查，去「剪辑设置」最下面的「版本更新」，点「检查更新」；同一个面板里还有「发布页」按钮（electron-ui/src/UpdateSettings.tsx:19）。

点「下载并安装」之前要满足几个前提（UpdateSettings.tsx:19；main.ts:257-264）：

- 先把正在跑的剪辑或 HUD 补充停掉，任务进行中会直接拒绝（main.ts:257）。按钮在忙的时候本来也是灰的（UpdateSettings.tsx:19）。
- 得是打包安装后的正式程序，开发预览会被退掉（main.ts:258）。
- 程序要能认出自己的安装位置，认不出会提示「请使用发布页安装」（main.ts:264）。
- 这个版本得能挑到可校验的安装包：文件名、三段式版本号、大小不超过 1 GiB、SHA256 必须是 64 位十六进制（electron-ui/electron/updateInstaller.ts:30）。

0.2.0 这类早期安装包没有应用内安装逻辑，第一次得从更新入口打开的 Release 页面手动下载 EXE，之后的版本才能用「下载并安装」（docs/development.md:23；main.ts:262）。

失败原因会直接显示在「版本更新」面板里（UpdateSettings.tsx:17），常出现的有：另一个程序窗口正在下载更新（updateInstaller.ts:39）、安装包校验失败请重新下载（:53）、无法下载安装包请稍后重试（:50）。安装那一步出错，原因会写进安装包旁边的 install.log，就在用户数据目录的 updates/ 里（scripts/update-install.ps1:7；main.ts:54），这个文件也会被打进诊断包（main.ts:214）。

程序日志在用户数据目录的 logs/（main.ts:27），单文件最多 1 MB、总量约 20 MB、只留最近 7 天（electron-ui/electron/diagnostics.ts:8）。要反馈问题就去「剪辑设置 → 诊断与反馈」，那里会显示日志位置，可以「导出诊断包」，也可以「打开日志目录」自己翻（electron-ui/src/DiagnosticsSettings.tsx:8）。

## HUD 认不出来的时候

程序是按 HUD 锚点打分来挑布局的，先试原始比例和 4:3 拉伸两种，画面比例还不到 1.55 时会再试一种横向也缩过的组合（hud_layout.py:72-73）。最高分低于 0.78，或者最高分和次高分差不到 0.025，就判成「未确认」—— 宁可判未确认，也不会悄悄按拉伸布局算下去（hud_layout.py:84-88）。

探测最多试 8 个时间点：头两个取「5 秒和录像 10% 里较小的那个」和「90 秒和 20% 里较小的那个」，另外两个是 25%、55%；录像长于 10 分钟再补上 40%、70%、85%、95%。一旦确认就停手，不会一直翻帧（hud_layout.py:94-98,109）。一个画面都没取到，会报「无法读取用于自动适配的录像画面」（:110）。

如果布局没确认、又没读到任何交战、而计划里本来是有候选的，程序会直接报错收工：「未能确认录像的 HUD 布局，无法可靠定位交战；本次未导出，请保留原录像并重新适配。」（hud_layout.py:117-118）所以不会出现看着成功、其实没成片的情况。

界面上对应的说明在剪辑设置里那条「识别适配说明」：已适配超宽、16:9 与 4:3 拉伸，无法确认时保留待核验，不推测计数（App.tsx:122）。

手头能做的是两件事。把同一个录像重新导入再跑一次，布局会重新适配一遍（app_worker.py:123-124；hud_layout.py:121-123）。或者改用按上面那三种已验证布局录出来的录像。至于手动指定 HUD 布局或缩放比例 —— HUD 设置里只有字段勾选，没有布局或比例选项，程序目前没有这个入口（HudSettings.tsx:5-13）。

## 几个具体问题

剪辑结果不对，先调哪个参数：动「合并间隔」（默认 10 秒，可填 0–600）和「交战前保留」/「交战后保留」（默认各 6 秒，上限分别 120 和 180 秒），都在首页「剪辑设置」里改（App.tsx:120；electron-ui/src/shared.ts:9；app_options.py:5-6）。

录像读不出索引：现在只走索引识别这一条路，它要求起始 PTS 为零的 H.264 MP4/MOV（indexed_coarse.py:37-42）。起始时间戳非零会报「视频起始 PTS 非零，实验模式尚未校准相对时间」，读不到索引会报「无法读取此录像的可靠 MP4/H.264 索引…」。碰到这种事，用 FFmpeg 把录像重新封装成起始时间戳为零的 mp4 是常见绕法，但这不是软件自带的功能（indexed_coarse.py:41-42）。

战绩栏里的 — 和 ≥2 是什么意思：见 README 的「怎么看识别结果」一节，这里不再重复一遍。

任务跑到一半想停：停止会保存断点，续接时沿用原任务的参数和算法版本（app_options.py:34-35；app_task.py:1）。
